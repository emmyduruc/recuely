# STT & VAD spike (Task 8)

**Date:** 2026-09-28 · **Machine:** Intel Core i9-9980HK (8 cores / 16 threads, no AVX-512/VNNI), 32 GB RAM, macOS 26.7 ·
**Code:** `spikes/stt/` (throwaway: `fixtures.py`, `stt.py`, `vad.py`, `score.ts`) · **Raw data:** `spikes/stt/results/`

## Recommendation

1. **STT: faster-whisper `base.en`, int8, greedy (`beam_size=1`), `language="en"`, `condition_on_previous_text=False`, no prompt.** A ~5 s take transcribes in 0.63 s (H-14 target ≤ 1.5 s), with no false advances in the fixtures. `tiny.en` is faster (0.35 s) and just as accurate on this synthetic audio, so it's the fallback if real takes show no difference. `small.en` (1.95 s) misses the latency target.
2. **Never bias STT with the chunk text** (`initial_prompt`). It caused a false advance and dropped half of two paused takes (H-15 refuted).
3. **VAD: Silero** (ONNX, MIT). It detected all 48 speech clips including 5 dB SNR noise, with a median onset of 72 ms and 7 ms CPU per second of audio. The energy VAD an AudioWorklet would run missed 4 of 6 clips at 5 dB and took up to 480 ms to detect speech (H-17 refuted). Where Silero runs (browser via `onnxruntime-web`, or streamed to the AI service) is decided in Task 13; either needs a §B8 entry.
4. **Only transcribe speech the VAD found.** On pure noise, `base.en` with beam 5 hallucinated "Good. Good. Great. Thank you … Bye. Bye. Bye …". Greedy decoding didn't, but VAD gating is the real guard.
5. **Biggest risk: assistant echo can look like a delivered take.** A clip containing only the assistant's voice at -20 dB was transcribed as the assistant's line ("Welcome back to the channel, everyone."), and Silero flags it as speech. If the speaker echo reaches the take while the creator is silent, the matcher would see the chunk's own words and **advance**. The engine arms the mic only after `settle`; Task 9 must measure the real echo tail with echo cancellation on and off and set `settleMs` so no residual remains (H-13, new H-27).

## Fixtures (synthetic)

48 takes plus 2 no-speech clips, built with Kokoro: 6 lines × 8 conditions. The creator voices are `am_michael` and `bm_george`; the assistant voice is `af_heart`. Audio is 16 kHz mono with 0.6 s lead-in and 1.0 s tail, so the true onset is known.

| Condition | Built as | Expected |
|---|---|---|
| clean | the line | advance |
| noise 10 dB / 5 dB | + pink noise at that SNR | advance |
| paused 2.5 s | 2.5 s of silence at the middle word | advance |
| paraphrase | a paraphrased version, chunk unchanged | advance |
| half-delivered | first half of the line | ask |
| another line | the next line instead | ask |
| assistant bleed -20 dB | last 0.5 s of the assistant reading the chunk, at -20 dB, in the lead-in | advance (creator does speak) |
| noise only / bleed only | no creator speech | no speech |

**Caveat:** synthetic voices are clean and regular, so the word error rates below are optimistic. **Latency numbers hold. Accuracy on real voices needs a few real takes** (see "Follow-up").

## STT: decisions with the app's matcher

`score.ts` runs each transcript through Task 6's `matchTranscript` with the §B7 default thresholds (0.80 / 0.70 / ending ±2). A *false advance* is an "ask" take that advanced; a *false ask* is an "advance" take that asked.

| Model | Prompt | False advances | False asks | Chunk words "heard" but never spoken |
|---|---|---|---|---|
| tiny.en b1 | none | **0** | 1 | 0 |
| base.en b1 | none | **0** | 1 | 1 |
| small.en b1 | none | **0** | 1 | 1 |
| base.en b5 | none | **0** | 1 | 1 |
| tiny.en b1 | chunk | 0 | 1 | 1 |
| base.en b1 | chunk | 0 | 2 | 2 |
| small.en b1 | chunk | 0 | 3 | 2 |
| base.en b5 | chunk | **1** (`l5-half`) | 1 | **7** |

- **The one false ask in every run** is the paraphrase "You just need three tools and about an hour" for "You only need three tools and about one hour". Three of nine words changed, so coverage is 0.78 < 0.80. Asking is the safe outcome here (§A6.3).
- **With the prompt**, `base.en` beam 5 "completed" a half-delivered take with the rest of the chunk, which is exactly the inflation H-15 feared. `base.en`/`small.en` also returned only the second half of two paused takes ("See you in the next video.", "Wait for the green light.").
- Every condition, including 5 dB noise, the 2.5 s pause and assistant bleed, has a median WER of 0–0.04 without the prompt.

## VAD

Silero v5 streaming (512-sample windows, start ≥ 0.5, end < 0.35 for ~100 ms) vs an adaptive energy VAD (20 ms frames, ≥ 12 dB over a running noise floor, 60 ms on / 200 ms off).

| | Silero | Energy |
|---|---|---|
| Speech clips missed (of 48) | **0** | 4 (`l1/l2/l3/l5-noise5`) |
| Onset latency median / min / max | **72 / 40 / 168 ms** | 40 / 20 / **480 ms** |
| 2.5 s mid-sentence pause: segment ends / speech restarts | 6/6 / 6/6 | 6/6 / 6/6 |
| False start on noise only | no | no |
| False start on assistant bleed (-20 dB) | `l2-bleed`, `l5-bleed`, `bleed-only` | `l1-bleed`, `bleed-only` |
| CPU | 7.2 ms per second of audio (Python + onnxruntime, 1 thread) | negligible |

The pause always ends the VAD segment and speech restarts afterwards. So the engine's silence timer (1200 ms) decides; the VAD never erases speech (E3). Assistant bleed is speech, and no VAD can tell voices apart: the guard is timing (`settle`) plus echo cancellation, not the VAD.

## Follow-up

- **Real takes:** record 5–10 takes in a normal room: clean, with a pause, a paraphrase, and half a line. Save them as WAV, and add them to `spikes/stt/audio/manifest.json` with their text. Then `stt.py` and `score.ts` give real-voice WER and decisions. Until then, accuracy is provisional.
- **Echo tail and settle time:** Task 9, on the real device matrix (this is the assistant-bleed risk above).

## Hypotheses

- **H-14** (`base.en` int8 transcribes a 5 s take in ≤ 1.5 s) → **Validated:** 0.63 s greedy (RTF 0.13).
- **H-15** (biasing with the chunk text doesn't cause false "delivered" matches) → **Refuted:** 1 false advance and 7 invented chunk words with beam 5; paused takes truncated. Don't bias.
- **H-17** (in-browser VAD is good enough without onnxruntime-web) → **Refuted** for an energy VAD: it misses speech at 5 dB SNR and can take up to 480 ms. Use Silero.
- **H-27 (new)** (with the §B7 settle time and echo cancellation, no assistant residual reaches a take in A1) → **Open, Task 9.** Residual at -20 dB is transcribed as the chunk and would advance.
